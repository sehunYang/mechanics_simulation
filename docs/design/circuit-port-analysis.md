# circuit_simulation → mechanics_simulation 이식 분석

> 목표: 형제 프로젝트 `circuit_simulation` 이 도달한 **"종합 교육용 웹앱"** 수준으로 역학 시뮬레이터를 끌어올린다.
> 이 문서는 회로 앱의 구조·기능을 분석하고, 역학 앱에 **무엇을 어떤 형태로 옮길지** 우선순위와 함께 정리한 것이다.
> 코드 작업 전 설계 기준 문서로 쓴다. (분석 기준일 2026-09-08)

## 1. 두 앱의 현재 위치

| 항목 | circuit_simulation | mechanics_simulation |
|---|---|---|
| 규모 | JS 약 12,600행 · CSS 12파일 · 테스트 2,200행 | JS 약 6,400행 · CSS 1파일 · 테스트 3,100행 |
| 모듈 구조 | IIFE + `window.App.<모듈>` 네임스페이스, `App.Events` 이벤트 버스, `App.State` 단일 진실 공급원 | 클래식 스크립트 단일 전역 스코프, `STATE` 전역 객체, 모듈 간 직접 함수 호출 |
| 편집·실행 | 모드 바 4개(편집·실행·비유·촬영), 모드 FSM 한 곳(`main.js`) | 하단 pill(실행/일시정지·초기화·촬영·무중력) + 배속 + 실행 배지 |
| 값 입력 | 더블클릭 number 팝업 | 숫자 키패드 모달 (모바일 친화, 더 낫다) |
| 측정값 표시 | 속성 패널에 전류·전압·전력·Q·Φ 등 **측정값** 상시 표시, 도선 배지, "이전→지금" 비교 | 속성 패널은 **입력값만**(질량·속도·μ·k). 실행 중 측정값 표시 없음 |

| 표시 토글 | ▶ 화살표 · A 배지 · Ω 값 · ⏚ · V 전위 지형 · Q 전하 | 궤적 on/off (요소별) |

| 안내 계층 | 시작 카드 · 상태 알림(오류→고치는 법) · 도움말 패널 · 확인 대화상자 | 경고 바(텍스트) · 확인 대화상자 |
| 공유 | URL 해시 공유 링크(`#c=…`) | 없음 (직렬화 코드는 이미 존재) |
| 촬영 | PNG 3배·자동 크롭·뷰포트 독립 | SVG 벡터 (동일 규격, 이미 우수) |
| 비유 모드 | 수로 3D (Three.js) | 해당 없음 |
| 문서 | README(교사용: 5분 도입·활동 8개·단원·단순화·FAQ) + ARCHITECTURE.md + 스크린샷 13장 + MIT LICENSE | README(개발자용) + QC/검증 보고서 3편 |
| 테스트 | Node vm 물리 검증 313 + 헤드리스 Chrome 화면 검증 144 | Node vm 물리 검증 173 + DOM 하네스(합성 이벤트) |

### 2-2. 공유 링크 (App.Share) — A

회로 `src/js/core/share.js` (103행). 소자·도선을 짧은 키 JSON → base64url → `#c=…`, 열 때 복원.

- 역학은 `Element.serialize()` · `FloorSegment.serialize()` · `Rope.serialize()` 와 `_serializeScene()`(history.js) 가 이미 있어 **직렬화 계층이 완성돼 있다.** 짧은 키 매핑 + base64url + `applyFromHash()` + 툴바 🔗 버튼만 추가.
- POE 예제·README 활동 링크·학생 배포에 곧바로 쓰이므로 **초기에 넣을수록 가치가 크다.**
- 주의: `id` 재발급, 앵커의 `elementId` 참조를 인덱스로 치환(회로의 `autoFor`/`couple` 처리와 같음).

### 2-3. 측정값 · 표시 토글 (속성 패널 + 배지) — B

회로는 "값을 바꾸면 그 순간 모든 수치가 바뀐다" 가 핵심 경험이다. 역학에는 대응 개념이 없어 가장 큰 교육적 공백이다.

| 회로 | 역학 번역 |
|---|---|
| 속성 패널 측정값(전류·전압·전력, `DC 개방` 배지) | 선택 물체의 **속도 v·가속도 a·운동에너지·위치에너지·역학적 에너지·알짜힘**, 실이면 **장력 T**, 바닥 접촉이면 **수직항력 N·마찰력 f(정지/운동 상태 배지)**, 용수철이면 **늘어난 길이·탄성력·탄성에너지**. 실행·일시정지 중에도 갱신(현재 panel.js 는 RUNNING 이면 그리지 않음 → 편집 입력은 잠그고 측정값 행만 갱신) |
| 도선 전류 배지(A 토글) | **속도 벡터 · 힘 벡터(자유 물체도) 배지** 토글. 화살표 길이 ∝ 크기, 값 라벨 병기 |
| 소자 값 라벨(Ω 토글) | 질량·μ·k·각도 라벨 토글 (촬영 시 빈 문항 그림 만들기에도 쓰임 — 회로 README 활동 8과 같은 용도) |
| "이전 → 지금" 3초 비교 배지 | 질량·각도를 바꾼 직후 가속도·장력의 이전값을 잠깐 병기 |
| 전위 지형(V) | 대응 없음 — 대신 **에너지 막대**(KE/PE/탄성/총합) 가 같은 역할 |
| 전하 카운터(Q, ∫i dt) | **이동 거리·충격량 누적**(∫F dt) — 선택 사항 |

구현 위치: `panel.js` 측정 행 + `render.js` 오버레이 + 토글 상태를 `STATE.show*` 로. 회로의 `_makeToggle(btnId, prop)` 패턴(`main.js` §_setupVisBtns) 그대로.

### 2-4. 그래프 패널 (과도 응답 그래프 · 오실로스코프) — B

회로 `transient-graph.js`(1,313행) 는 회로 해석 전용 로직이 대부분이라 **코드 이식 대상이 아니다.** 가져올 것은 **패널 UI 골격과 규약**:

- `#transient-panel` 고정 위치 카드 + 토글 행(소자별 켬/끔) + 범례 + 닫기, `📈` 버튼으로 다시 열기(닫으면 되살릴 방법이 없던 문제를 `Guide.toggleGraph` 로 해결한 이력).
- 실행 시각을 `run:time` 이벤트로 흘려 **세로 시간 커서**를 그린다.
- 곡선 색 팔레트(`_colors` 6색, 인쇄 명도 구분) 그대로.

역학 그래프: 물체별 **x-t · v-t · a-t · E-t**, 용수철은 **x-t(진동)**, 충돌은 **운동량 p-t**. 데이터는 이미 `recordTrails()` 가 위치를 매 스텝 기록하고 있으므로 v·a·E 를 같은 자리에서 함께 기록하면 된다(`TRAIL_MAX_POINTS` 상한 규칙 재사용). 회로처럼 **곡선 위에 식을 적는 것**(`v = v₀ + at` 의 a 값, 진동 주기 `T = 2π√(m/k)`) 은 2차 목표.

### 2-5. POE 예측·관찰·설명 활동 — B (핵심)

회로 `src/js/ui/poe.js` (889행). 가져올 것은 **엔진(약 330행)**, 바꿀 것은 **예제 데이터**.

엔진에서 그대로 옮길 것:
- 예제 스키마 `{id, cat, title, level, misconception, circuit→scene, question, options[{label,correct|tag}], observe, explain, select, vis, variants, measure}`
- 단계 FSM: 목록(분류 탭·진행률·CSV) → 예측(선택지 **결정적 셔플** `_optionOrder`) → 관찰(실행 모드 자동 진입, 배지 자동 켬, 지정 요소 자동 선택) → 설명(정답 문장·내가 고른 답·오개념 태그·다시 풀기·다음 예제)
- 결과 누적 `_results` + `exportCSV()` (BOM 포함 UTF-8)
- 장면 정의 DSL: 회로의 `C(key,type,gx,gy,…)` / `W(a,ap,b,bp)` → 역학은 `B(key,'rect',gx,gy,{mass,vx})` / `F(x1,y1,x2,y2,{mu})` / `R(keyA,ptA,keyB,ptB)` / `P(...)` / `S(...)`. 로더는 `_deserializeScene()` 을 재사용.

번역이 필요한 것:
- **회로는 정상상태 해가 있어 `Solver.solve()` 한 번으로 관찰값을 얻지만, 역학은 시간 진화다.** → 관찰값 정의를 "시각 T 의 값" 또는 "사건 시각의 값(바닥 도달·충돌·정지)" 으로 두고, 화면과 무관하게 장면을 N 초 돌리는 **`simulateHeadless(scene, T|event)`** 를 physics.js 에 추가해야 한다(test/harness.js 가 이미 같은 일을 Node 에서 하고 있으므로 그 경로를 브라우저에서 호출 가능하게 정리).
- 진리표(`truth`) → 역학에는 없음. 대신 **비교 표(`variants`)** 가 주역: "질량 2배 / 각도 2배 / μ=0" 를 줄 클릭으로 바꿔 측정값을 나란히 채우는 회로의 `variantObserve` 를 그대로 쓴다.

역학 예제 분류 초안 (회로의 6분류 ↔ 역학 6분류):

| 분류 | 다루는 오개념 · 예제 후보 |
|---|---|
| 힘과 운동 | 무거운 것이 먼저 떨어진다 · 운동에는 힘이 계속 필요하다 · 힘이 0 이면 멈춘다 · 등속 vs 등가속 |
| 마찰 · 빗면 | 빗면 가속도는 질량과 무관 · 정지 마찰은 최대값이 아니다 · μ 를 키우면 항상 느려진다? · 마찰이 있어도 미끄러지지 않는 조건 |
| 실 · 도르래 | 아트우드 장력은 무게보다 작다 · 실 양쪽 장력은 같다 · 움직도르래 힘 절반·거리 2배 · 실이 늘어지는 순간 |
| 용수철 | 주기는 진폭과 무관 · 무거우면 느리다 · 최대 속력은 평형점 · 두 용수철 직렬·병렬 |
| 충돌 · 운동량 | 큰 물체가 밀린다? · 완전탄성 vs 비탄성 · 정지 물체와 같은 질량 충돌 = 속도 교환 · 반발 계수 |
| 에너지 | 역학적 에너지 보존 · 마찰로 잃은 양 · 높이가 같으면 속력이 같다(경로 무관) · 용수철 탄성에너지 |

### 2-6. 모드 바 · 툴바 정리 — C

회로의 하단 **모드 바(편집·실행·비유·촬영)** + 왼쪽 아래 **undo/redo·표시 토글·공유·POE·그래프·도움말 바** 배치는 UI 밀도가 높아져도 정리된 인상을 준다. 역학은 하단 pill(실행·초기화·촬영·무중력) 에 배속·실행 배지가 따로 떠 있음.

- 제안: 하단 pill 은 유지(역학은 실행/일시정지/초기화가 자연스럽다). 왼쪽 아래 undo/redo 옆에 회로식 **토글 바**를 두고 벡터·값 라벨·궤적·🔗·POE·📈·? 를 배치.
- 비유 모드는 **이식하지 않음** (역학은 그 자체가 직관 모형이다).

### 2-9. 헤드리스 Chrome 화면 검증 — A

회로 `tests/browser/lib.js`(86행) + `run.js`. puppeteer-core 로 실제 페이지를 띄워 **사용자에게 보이는 값**(패널 행 텍스트·캔버스 픽셀)을 닫힌형 공식과 대조하고, 같은 실행에서 README 스크린샷을 찍는다.

- 역학의 `test/dom-harness.js` 는 합성 이벤트를 Node vm 에서 흘리는 방식 → 렌더 결과(픽셀·레이아웃·모바일 뷰포트)는 못 본다. 보완 관계이므로 **둘 다 유지**.
- `lib.js` 는 `build()` `focus()` `select()` `mode()` `shot()` 만 역학 API 로 바꾸면 그대로 쓴다.

## 4. 제안 로드맵

> **구현 현황 (2026-09-08)** — 아래 로드맵 4단계와 `persona-rubric-evaluation.md` §6 의 보정 항목이 모두 구현되었다.
> 1단계 기반(이벤트 버스·장면 DSL·갤러리·공유 링크·시계열 CSV·안내 계층·경고 규칙·느린 배속·한 스텝·CSS 토큰 통일·캐시 버스터),
> 2단계 측정·시각화(자유물체도 분해·측정값 패널·속도/힘 벡터·값 라벨 토글·시간 그래프·잔상 비교·실행 중 선택),
> 3단계 교육 활동(헤드리스 측정·POE 24문항·수치 문항·비교표·해설 8·탐구 카드 10·파라미터 스윕·공기저항),
> 4단계 문서·검증(교사용 README·ARCHITECTURE·LICENSE·스크린샷·헤드리스 Chrome 검증 41항목). 비유 모드는 계획대로 이식하지 않았다.

각 단계는 독립적으로 배포 가능하며 앞 단계에 의존한다.

> 페르소나 네 유형(흥미·학습 보조·개념 점검·심화 탐구)으로 채점한 결과와 그에 따른 **보정 항목**(느린 배속·장면 갤러리·시계열 CSV·자유물체도·실행 겹쳐 보기·파라미터 스윕·수치 예측형 문항 등)은 `persona-rubric-evaluation.md` §5~6 에 있다. 기획 시 이 로드맵과 함께 읽는다.

**1단계 — 기반 (A 등급, 1~2 세션)**
1. `?v=` 캐시 버스터, `LICENSE`
2. CSS 토큰 이름을 회로와 통일 + 파일 분할
3. `EVENTS` 버스 도입 (`state:changed` · `run:time` · `mode:changed`)
4. **공유 링크** (`share.js` 이식)
5. **안내 계층** (시작 카드·도움말·상태 칩) + `validateAll()` 경고 규칙 채우기

**2단계 — 측정과 시각화 (B, 2~3 세션)**
6. 속성 패널 **측정값 행** (v·a·E·T·N·f, 실행 중 갱신)
7. **표시 토글 바** (속도 벡터·힘 벡터·값 라벨·궤적) + "이전→지금" 비교
8. **그래프 패널** (x/v/a/E-t, 시간 커서, 📈 재열기)
9. 우클릭 메뉴(복제·삭제), 모바일 info/graph 버튼

**3단계 — 교육 활동 (B, 3~4 세션)**
10. `simulateHeadless(scene, T|event)` — 화면 없이 장면을 돌려 측정값을 얻는 경로
11. POE 엔진 이식 + 장면 DSL + 비교표(variants)
12. 역학 POE 예제 세트 (6분류 × 3~5개 = 약 20개) + CSV

**4단계 — 문서와 검증 (A, 1~2 세션)**
13. 헤드리스 Chrome 검증 스위트 + 스크린샷 자동 생성
14. README 교사용 재구성 (활동·발문·단원·단순화·FAQ) + ARCHITECTURE.md 분리
